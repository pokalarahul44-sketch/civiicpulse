A reproducible score, with an explanation for every component.

The priority score

30% demand + 35% infrastructure deficit + 20% vulnerability + 15% plan alignment

All components use a 0–100 scale. Demand is requests per 100,000 residents, capped at 100 points when there is one request per 100,000 residents. These thresholds and weights are illustrative, not validated public policy.

All stored requests contribute to demand, including resolved requests, so this is a historical demand signal rather than an open-issue backlog. Exact repeated text in the same district is rejected; semantic duplicate detection is not implemented.

What is real in this demo?

Submission, filtering, status updates, score calculations, persistence and brief downloads work locally. The seeded requests and district baseline numbers are fabricated for demonstration. New requests are marked separately.

Gemini analysis and Firestore storage are optional live integrations that need your Google Cloud project. Audio analysis is available only in live mode. Project briefs use a deterministic template so their numbers agree with the dashboard.

Before a real pilot

Replace sample baselines with versioned, licensed government datasets. Validate language quality, sampling bias and scoring weights. Add separate citizen and official access, consent, retention rules and audit logs. Verify cost estimates and existing works with the responsible department.

Digital Public Good direction

This is an independent prototype intended as a starting point for an open, reusable tool. It is not a certified Digital Public Good. Licensing, documentation, privacy assessment and independent review remain release tasks.
